# Roadmap

Forward-looking work items for the HiBy R1 Audiobook Firmware Mod.
Historical development tracking is archived in
[docs/dev-history/firmware-improvement-plan-archive.md](docs/dev-history/firmware-improvement-plan-archive.md).

## Safer Extension Points

1. **Harden the on-device DB helper** while preserving the current UI/resume path.
2. **Add repeatable local fixture tests** for DB helper behavior.
3. **Build a candidate helper binary** and test it through ADB as a runtime-only
   replacement before building or flashing a new firmware package.
4. **Only after runtime tests pass**, build a new firmware candidate with a new
   version marker.

## Longer-Term Research

- **Real `hiby_player` UI work**: a native Audiobooks page would be cleaner than
  the current genre-route and daemon workaround, but it requires deeper binary/UI
  reverse engineering.
- **Static UI xref work**: the repeatable report at
  `work/static-xrefs/hiby_player-1.6.23-xrefs.md` (generated by
  `tools/r1_hiby_player_static_xrefs.py`) identifies useful next RAM-only targets
  around stock media route records (`0x00787040`) and listview handlers:
  - `vg_listview_artist -> 0x00490ec0`
  - `vg_listview_album -> 0x00490ee0`
  - `vg_listview_genre -> 0x00490f40`
  - `vg_listview_book -> 0x00490fa0`
  
  This is the next path for a cleaner Audiobooks submenu or Author/Series views.
- **Route-callback analysis**: the simple route callback only reads `view` and
  `child` pointers, while the chained callback reads `view`, `child`, and `next`.
  The current launcher calls the simple callback with the genre-chain record, so
  callback-field-only edits cannot fix Back behavior. Future UI-view work should
  target native list/query internals or a catalog-backed custom entry point.
- **Author/Title/Series subviews**: tracked in
  `docs/audiobook_views_research.md`. Title is the current stable route; Author
  may be testable through stock artist routes but needs catalog isolation;
  Series has catalog data when Seanap/Plex-style folders are present but still
  needs custom UI/query work.
- **True direct resume**: the `0x49e200` shared media-open path is proven
  on-device for off-screen row indexes. The one-shot native direct-open helper
  can force the next stock row-open call to the saved zero-based track index.
  The older visible-row swipe/tap path remains as fallback.
- **Better metadata parsing** inside the on-device helper: possible for simple
  ID3 tags, but higher risk and more code size. The current safer path lets the
  stock scanner provide metadata when possible and uses folder/file fallback
  otherwise.
- **QEMU system emulation**: useful someday for release validation, but not ready
  yet. Local host-native helper tests and live ADB runtime tests remain more
  useful right now.
- **Playback-mode handling**: live R1 snapshots mapped `/usr/data/user.ini`
  offset `0x250` (`592` decimal) as the Now Playing play-mode byte. Development
  builds target value `3` (list loop) for active audiobooks using the Now Playing
  framebuffer guard before tapping the mode button.
- **Audible-inspired features**: sleep timers, bookmarks/notes, narration speed,
  and car/driving controls would require deeper UI work or a new input
  convention. These should wait until the current resume and browsing path is
  production-stable.

## Next Device Tests

1. **Runtime-only install the new MIPS DB helper** and run Music -> Update Database.
   Verify:
   - Audiobooks with `Audiobook`, custom audiobook-like, or blank genre tags all
     appear in Audiobooks.
   - Music Albums/Genres still do not show audiobook albums/genres.
   - A title like `The Amber Book` or `The Hobbit` appears under `A`/`H`, not
     `T`, if such a fixture is available on the SD card.

2. **Check `batd` existence** before treating `-DisableBatdLogger` as a real
   performance improvement. If `batd` exists, flash a dev candidate with
   `-DisableBatdLogger` and test normal music responsiveness for at least an
   hour with Bluetooth both off and on. Confirm no `/mnt/sd_0/batlog.txt` growth.

3. **Re-run a multipart audiobook resume check** after any DB helper change to
   make sure normalized sorting does not disturb saved-file lookup.

4. **Direct-resume research**: arm the guarded play-open tracer with an audited
   cave such as `0x760708`, select a normal music row and an audiobook track row,
   then read `PLAY_OPEN_SCRATCH` to compare the stock function arguments. The
   controlled test confirmed that forcing `a2=4` while tapping row 1 opened
   The Road part 5, and forcing `a2=20` while tapping row 1 in the 44-track
   The Remaining Aftermath list opened part 21. Off-screen direct track
   selection is possible once the correct book's track list is open.

5. **Quick book-switch stress testing**: start or resume one audiobook, then
   select a different audiobook title quickly (preferably multipart). Confirm
   the new book resumes at its saved file/position and the daemon log does not
   show a stale `book-title direct-start memscan root=` from the previous book.

6. **Battery/responsiveness monitoring**: run the read-only runtime monitor while
   music is playing for at least 2 hours to check for reboots, daemon
   duplication, or memory issues.

## Next Live Tests

When the R1 is available again, the most useful tests are:

1. Install the latest resume runtime without flashing and test multipart
   title-tap resume from the Audiobooks title list.
2. If the result is odd, collect a debug bundle before rebooting.
3. For battery or music-playback responsiveness, run the read-only runtime
   monitor.
4. Before building or flashing another candidate, run the consolidated local
   sanity wrapper.
5. Use the unified ADB controller to capture screens and drive common UI steps.
6. Repeat with pre-play direct start disabled to compare fallback behavior.
